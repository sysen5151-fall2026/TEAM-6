# Model 11.0: what changed from 10.9

`EcoCommute_11.0_accounts_transit.xml` is the 10.9 export plus what the app gained after 10.9 (prompt-log entries 021-024 and the later accounts and place-picker work). It is generated by [scripts/build_model_11_0.py](scripts/build_model_11_0.py) (`python -I docs/model/scripts/build_model_11_0.py`) and checked by `tests/test_model_11_0.py`. **The first import is described below.** The file is named 11.0, not 10.10, so that a plain sort of the export names still ends with the newest one (`tests/test_model_linkage.py` reads the last file).

45 new entities and 276 new relationships. Nothing in 10.9 was removed; two descriptions were reworded (below). Every new requirement is a Draft with all quality flags false.

## Why

After 10.9 the app gained features the model did not describe (the ADRs say so): the bus from the real TCAT timetable (ADR 0007), vehicles the Commuter has and the carpool share (ADR 0006, 0008), place suggestions while typing, and invite-only accounts with saved trips and a persistent cache (ADR 0009). The two earlier requirements that still said the bus time is typed were wrong.

## First import (2026-10-29): Intelligence 74%, three errors, fixed in this file

- "Input/outputs not satisfied by any requirement": Bus Schedule and Signed-in Session. They now satisfy 3.2.11 and 3.3.1.13 (schedule) and 3.1.1.14 (session).
- "Prior action is dependent on the later action" on UC.3 and UC.4. The cause is **inferred, not seen**: the first file had flows that skipped steps (UC.3.12 to UC.3.14, UC.4.2 to UC.4.4, UC.4.3 to UC.4.5) and every flow in 10.9 joins neighbouring steps. The steps were renumbered (publish moved last) and the flows made neighbour-only. The file must be imported again to know whether that was the cause.

## The "prior action" error (2026-10-29): cause found, fixed in this file

Pure 10.9 imported into a fresh project gave the same "prior action is dependent on the later action" error on UC.3, so it is older than 11.0; re-importing the same file into the same project made it disappear (which is why 10.9 once showed 81% with no errors). Innoslate's Fix dialog says: an action later on the timeline cannot trigger an earlier action ("time-traveling input/outputs"). It listed Route Options, Mode Comparison, Mode Choice (UC.3) and Account Details (UC.4). The timeline is the chain START, step 1, step 2, ..., END in the **parent action's simulation data**; UC.1 and F.2, drawn in Innoslate, have it, but the UC.3 parent (made by script in 10.9) and the new UC.4 had only START and END, so Innoslate guessed an order. `write_timelines` now writes the chain for UC.3 (steps 1-15) and UC.4 (steps 1-5) in number order, and `tests/test_model_11_0.py` checks the chain and that every flow goes forward along it. Giving every action its own control-structure ids (`unique_control_structure_ids`) did **not** fix it; it is harmless and kept. Trip Options flows from UC.3.12 to UC.3.13 again: the earlier "looping" error was left over from importing older versions into the same project, so import this file into a new project.

**Result: imported once into a new project, Intelligence 77% with no errors (warnings only).**

## Not done, and not claimed

- **Not imported.** Only the file structure was checked by script and tests. Intelligence may report new errors or warnings (the "generated but not received" kind for Place Suggestions is expected; X.7 performs only UC.3.12).
- **Function allocation is provisional.** The new functional requirements are allocated to the existing F.2.2-F.2.5 and the system-wide ones to F.2, as in 10.9; no new F.x functions were added.
- **Not modeled:** carpool is covered by 2.1.16 and UC.3.12 but has no step of its own (the share is computed inside UC.3.8); the persistent place cache is covered by 3.3.1.17 and 3.4.5.7 only; log-in lockout, password change and data export are in 3.3.1.15 and 3.4.5.6, not separate actions; the bus emission factor is still the placeholder (O-2).
- **Numbers are proposals:** 2 to 8 people, 5 wrong passwords in 15 minutes, 90% suggestion hit rate, and the default of owning no vehicle.
- **Open from earlier:** TR.10 (trip labels finer than coarse location) is unresolved and now also applies to the stored accounts.
